# Examples

以下示例用于帮助宿主理解 `pair-program` 的调用场景和输出预期。

## 典型调用

1. 评审需求方案

`/pair-program -n 5 帮我评审这个登录功能 PRD，重点看遗漏流程和验收标准`

2. 对比技术方案

`/pair-program -n 6 比较把缓存放在 BFF 还是服务层更合适，结合当前项目上下文给建议`

3. 评审重构计划

`/pair-program -n 5 基于当前仓库，评估订单模块重构计划的风险和分步迁移方式`

4. 生成测试策略

`/pair-program -n 4 针对这次支付回调改动，给我一份回归测试和上线验证清单`

5. 继续承接当前上下文

`/pair-program -n 3 继续看我们刚才讨论的接口分页方案，直接给结论`

6. 先讨论再落代码

`/pair-program -n 5 基于当前仓库实现订单列表筛选，先内部讨论实现路径和回归风险，再改代码并给验证结果`

## 角色切换示例

- 用户在看 PRD：副智能体更像 `challenger`
- 用户在看架构：副智能体更像 `architecture reviewer`
- 用户在看代码实现：副智能体更像 `code reviewer`
- 用户在看测试/发布：副智能体更像 `verifier / release reviewer`

## 输出预期

默认输出：

1. `主结论`
2. `内部讨论摘要`

存在关键分歧时追加：

3. `分歧点`
4. `建议选择`

不要默认输出完整逐轮对话。

即使用户明确要求查看内部讨论全文，也只返回清洗后的结构化摘要、关键分歧和结论，不返回逐轮 transcript。
