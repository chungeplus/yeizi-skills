# `TypeScript` 抛错规则标题澄清设计

## 目标

把 `rules/technologies/typescript/implementation-rules.md` 里的规则标题从“`抛错只用 Error 实例`”改成更准确的表述，避免标题被误解成“只能抛 `new Error()`，不能抛自定义错误类实例”。

## 本次范围

本次只处理下面 1 件事：

- 修改 `rules/technologies/typescript/implementation-rules.md` 里这条规则的标题文案

本次不处理下面内容：

- 不修改这条规则的正文语义
- 不新增新的错误处理约束
- 不补更多推荐或不推荐示例
- 不扩展到其他语言或其他规则文件

## 现状与问题

当前标题是“`抛错只用 Error 实例`”，但正文已经写成“只使用 `Error` 或继承 `Error` 的错误实例，不抛字符串，也不抛临时对象”。

这会带来一个轻微但真实的理解偏差：正文允许抛 `Error` 子类实例，标题却像是在收窄成只允许 `Error` 本身的实例。

## 结论

把标题改成：

### 抛错只用 `Error` 或其子类实例

这样处理的原因：

- 和当前正文语义完全一致，不额外改规则范围
- 比“`Error` 实例或者 `Error` 子类的实例”更短，适合标题
- 比原标题更不容易被误解成排斥自定义错误类

## 执行检查点

1. `implementation-rules.md` 这条规则标题更新为“`抛错只用 Error 或其子类实例`”
2. 规则正文继续保留“`Error` 或继承 `Error` 的错误实例”这层语义
3. 推荐与不推荐示例保持不动，避免这次小改动扩散

## 完成标准

- 读标题的人能直接知道：允许抛 `Error`，也允许抛 `Error` 子类实例
- 标题与正文不再存在范围表达不一致
- 本次修改只停留在文案澄清，不顺手扩规则
