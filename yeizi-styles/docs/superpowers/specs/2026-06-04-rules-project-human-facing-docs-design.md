# rules-project 人类规则源定位设计

## 背景

`rules-project` 当前承载三类内容：
- `rules/projects/*`：共享项目规则
- `rules/technologies/*`：通用技术规则
- `rules/scenes/*-rules.md`：业务场景规则源

这三类内容的共同点不是“都给 AI 执行”，而是“都先给人类阅读、确认和修改”。

现在的 `README.md` 和 `AGENTS.md` 已经能说明目录边界和基本流程，但还没有把下面这几个核心事实集中写清楚：
- 整个项目的规则形成流程分成三段
- 共享规则、技术规则、场景规则都属于同一类人类规则源
- `generate-scene-rules` 生成的场景规则不是例外，仍然必须遵守 `rules-project/AGENTS.md`
- 这里不存在“人工规则一套写法、skill 生成规则另一套写法”的双轨标准

## 目标

- 让 `README.md` 清楚说明 `rules-project` 的整体运行流程
- 让 `AGENTS.md` 清楚约束三类规则源使用同一套人类可读写法
- 明确 `generate-scene-rules` 生成的 `rules/scenes/*-rules.md` 也必须遵守 `AGENTS.md`
- 在不重排整份文档的前提下，补足当前定位说明

## 不做的事

- 不重写现有 `写法要求`、`工作方式`、`场景规则生成` 的主体规则
- 不引入外部参考项目名称和链接
- 不修改 `rules-project` 之外的工作区文档
- 不在这次设计里顺手调整 scene rules、technology rules 或 skill 流程细节

## 运行流程定位

`rules-project` 的规则形成流程固定分成三段：

1. 项目开发者参考其他项目并结合自己的开发经验，整理共享项目规则，写入 `rules/projects/`
2. 项目开发者根据自己的编码习惯，整理通用技术规则，写入 `rules/technologies/`
3. 项目开发者通过 `generate-scene-rules` 生成对应业务的场景规则源，写入 `rules/scenes/`

这三段流程产出的内容都属于规则源，默认先服务于人类阅读、确认和修改，不写成只方便 AI 消费的压缩表达。

## README.md 设计

### 新增项目流程小节

在 `目录说明` 之后新增 `## 项目流程` 小节，用来集中说明这套项目是怎么运转的。

这个小节固定说明 4 件事：
- 共享项目规则的来源和落点
- 技术规则的来源和落点
- 场景规则由 `generate-scene-rules` 生成并落到 `rules/scenes/`
- 三类规则都先按人类可读规则源来写

### 保留使用方式小节

继续保留现有 `## 使用方式`，但只负责讲操作顺序，不再承担项目定位说明。

`使用方式` 固定按下面顺序描述：
1. 先补共享规则、技术规则和场景基线
2. 再生成或重写场景规则草案
3. 先给人确认
4. 确认后再真正写入文件
5. 最后再交给 `agents-project` 生成最终 AI 产物

### README 的表达边界

- 只说明项目如何运转，不展开 `AGENTS.md` 里的具体写法细则
- 只写抽象来源类型，不写外部参考项目名
- 让第一次进入 `rules-project` 的人可以直接看懂三类规则分别怎么来、放哪里、先给谁读

## AGENTS.md 设计

### 新增规则来源和统一写法小节

在开头说明之后、`## 写法要求` 之前新增 `## 规则来源和统一写法` 小节。

这个小节固定收 4 条约束：

### 共享规则先按人类可读写

`rules/projects/` 里的共享规则由开发者参考其他项目并结合自己的开发经验整理，但写出来后首先是给人类读和改的，不写成只方便生成的压缩表达。

### 技术规则先按人类可读写

`rules/technologies/` 里的技术规则由开发者根据自己的编码习惯整理，同样属于给人看的规则源，表达方式继续遵守整份 `AGENTS.md`。

### 场景规则也遵守同一写法

`generate-scene-rules` 负责生成 `rules/scenes/*-rules.md`，但它生成出来的内容仍然是规则源，不是最终 AI-facing 成品，所以必须遵守同一套人类可读写法。

### 所有规则源只用一套标准

共享规则、技术规则、场景规则都按同一套标题写法、正文组织、语义化表达和可判对错要求来写，不区分“人工一套、生成一套”。

### AGENTS 的表达边界

- 这个新增小节只负责先把总原则讲清楚
- 现有 `写法要求` 继续作为统一写法的具体展开
- 现有 `场景规则生成` 继续作为 `generate-scene-rules` 的专项约束
- 不把这次新增内容写成来源流水账或大段背景说明

## 一致性要求

文档修改后，下面几件事必须同时成立：

- `README.md` 能让人一眼看懂三段流程和项目运行顺序
- `AGENTS.md` 能让 AI 明确知道三类规则源使用同一套 human-facing 写法
- `generate-scene-rules` 不会被理解成可以绕开 `AGENTS.md` 单独产出另一种文风
- `README.md` 讲流程，`AGENTS.md` 讲约束，两者分工清楚但口径一致

## 完成标准

- `README.md` 的 `使用方式` 明确区分“流程定位”和“操作顺序”
- `AGENTS.md` 新增 `规则来源和统一写法` 小节
- `AGENTS.md` 明确写出 `generate-scene-rules` 生成的场景规则也必须遵守同一套写法
- 两份文档都体现“所有规则先给人类阅读和修改”的定位
- 两份文档都不引入未确认的新流程、新来源或新边界
